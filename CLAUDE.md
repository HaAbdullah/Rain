# Rain

A personal launcher for Windows: Tauri 2 shell, Vue 3 frontend, Rust backend. One user, one PC.

## How to work here: the fast loop

The owner is a software engineer and reviews small changes himself, in the running app.

1. **Keep the live app running.** `npm run dev` (browser tab, `http://localhost:1420`, launch
   entry `rain-live`) or `npm run dev:app` (the real window). Both run on a copy of the owner's
   real data, so the screens look like the installed Rain and nothing can damage real files.
2. **Edit the main tree directly.** A frontend edit shows in under a second (Vite hot reload). A
   Rust edit rebuilds and restarts the backend by itself in about 6 seconds. A change in
   `crates/rain-types` also regenerates `src/bindings/rain-types.ts`.
3. **Look at it in the live app**, then run only what is near the change: `npm run check:quick`
   (compiles Rust and TypeScript, runs the frontend tests, about half a minute) or one test file.
4. **Commit locally.** Do not push unless asked.

Do NOT, for an ordinary change: start subagents or a workflow, run a review pass, run the full
`npm run check`, build a release, or install. That whole cycle belongs to `/rain-review` and runs
only when the owner types it. A large feature may be built by parallel agents (Sonnet) when the
owner asks for speed, but its result goes into the live app first and gets no review loop either.

| Command | What it is for |
|---|---|
| `npm run dev` | Live app in a browser tab, on a copy of the real data |
| `npm run dev:app` | The same in the real window (maximise, zoom, drag, hide). Attaches to a running `npm run dev` |
| `npm run dev:empty` / `dev:fixture` | Live app on empty folders / on the test fixture data |
| `npm run check:quick` | Compile and frontend tests, for the edit loop |
| `npm run check` | The full checklist (format, lints, all tests, build, start). `/rain-review` only |
| `npm run install:local` | Release build into `%LOCALAPPDATA%\Programs\Rain`. `/rain-review` only, or when asked |
| `npm run types` | Regenerate the TypeScript types from `rain-types` |

What the browser tab cannot show: maximise, real zoom, window dragging, the global hotkey, hide on
blur. Use `npm run dev:app` for those. The dev window is a separate app for Windows; the installed
Rain keeps running next to it and keeps Ctrl+`.

## Map

- `src/` Vue app. `features/<screen>/` one folder per screen, `nav/routes.ts` the screens,
  `keys/keymap.ts` the one key table, `actions/` what Enter and Ctrl+K do, `data/api.ts` the one
  interface to the backend, `styles/tokens.css` every colour (themes).
- `crates/rain-backend/` the backend (`rain-backend.exe`), served over a named pipe under
  `/api/v1`. `modules/<name>/` one folder per feature (routes, service, store).
  `platform/` is the ONLY place for `unsafe` and Windows API calls (`tests/source_rules.rs`).
- `crates/rain-types/` the wire types. The TypeScript file is generated from them.
- `src-tauri/` the window (`rain.exe`): hotkey, hide and summon, starts the backend.
- `docs/ui-spec.md` and `docs/backend/*.md` the design. Update the part you change.
- `scripts/` dev, check and install commands.

## Rules that are not negotiable

- **The Obsidian vault is the owner's personal database.** Rain writes only habit ticks, only in
  the vault folder `Rain`. Nothing generated by an AI goes into the vault. Never read or write the
  vault or the real data folder (`%APPDATA%\Rain\machine.toml` says where it is) while developing;
  the dev copy in `.rain-dev/` is for that.
- **`~/.claude` is read only** for Rain's code and for you. The switch "Monitor Claude sessions"
  (it edits `~/.claude/settings.json`) stays off unless the owner turns it on.
- **Game mode must never close a real program in a test or a dev run.** Tests use the fakes; a
  sandbox backend has no access to the PC's programs.
- **Low cost when idle.** Rain is hidden most of the time: nothing polls, reads or animates while
  it is hidden, and a screen loads its data when it is opened, not at start.
- No sample data in the app. A state is shown with real or fixture data.
- Plain language in the UI and in comments. Commit messages say what changed for the user.
